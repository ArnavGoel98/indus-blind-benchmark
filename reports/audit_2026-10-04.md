# Audit before prose (2026-10-04): the 93% corpus, and length vs size at equal tokens

Inspection and reanalysis only. Methods frozen at `frozen-v1`; no experiment was rerun. One corpus was
regenerated deterministically to inspect it.

## Item 4: the generator-v2 corpus scoring 93% under the original (frozen) rule

**Corpus:** generator-v2, Sanskrit, **syllabic** (not alphabetic), seed 0, 2,906 texts × 4.6 signs,
duplicates 0.22, 471 sign types, candidates tier. The original rule selected `sanskrit-sister`.

| Check | Result |
|---|---|
| Regenerate and re-run deterministically | 93.0% tokens (type accuracy 53.7%), same reference chosen: **reproduces** |
| Shuffle the predicted values across signs (20 permutations) | 0.9% mean, 3.0% max: **the scorer is not generous; no scoring bug** |
| Same corpus, no-relative tier | 0.0% (revised rule 8.0%): high only when the sister is chosen |
| Answer-key leakage into the solver | **None found.** The solver sees only sign-ID sequences plus the reference corpora. |
| Score before the cognate translation | **57.6%** (raw sister units). The solver's `_translate` step (frozen method code, `decipher.py:24-28`) maps sister units to hidden-language units using the TRUE sound correspondences (`Reference.to_hidden`: 352 entries, 168 changed). That step adds +35 points. |
| Text overlap between hidden texts and the sister's source half | **74%** of this corpus's texts occur word for word inside a clause of the reference half. |

Other generator-v2 Indus-point corpora above 50% under the original rule (all candidates tier, all choosing their sister): Latin syllabic 95.6%, Sanskrit syllabic seed 1 91.6%, Finnish syllabic 92.7%, Tamil syllabic 90.6%, Tamil logosyllabic 87.2%, Sumerian alphabetic 57.0%.

### What this means: not a bug, but two design properties that inflate every tier that includes the sister

1. **Oracle sound correspondences.** Whenever the solver picks the sister, it is given the true
   phoneme correspondences between sister and hidden language for free. Documented as "cognate credit"
   (limitation 5.2), but its size was not quantified before: on this corpus it is worth 35 points.
   This sits in frozen method code, so it cannot be changed without unfreezing; it can only be
   reported.
2. **The sister shares the hidden corpus's text material.** It is the same source text, phoneme-
   relabelled, with 20% of word types replaced. Clauses are split into halves by clause index. Every
   language has repeated clauses, so identical clauses land in both halves:

| Language | Hidden clauses identical to a reference clause | v1 Indus-point texts found word for word in the reference half | ... after removing those shared clauses |
|---|---|---|---|
| Sanskrit | 30% | 50% | 49% |
| Tamil | 6% | 42% | 41% |
| Sumerian | 60% | 90% | 76% |
| Latin | 13% | 57% | 57% |
| Finnish | 19% | 90% | 82% |

   Most of the containment is not caused by the split itself: short seal-like windows (2-3 words)
   recur naturally in a large text of the same language. The split defect (identical clauses in both
   halves) adds up to 14 points for Sumerian and 8 for Finnish. A real relative would share far fewer
   exact phrases, because word order, morphology and vocabulary diverge.

**Which results this touches.** The related and candidates tiers (every Task D number with the sister
available), and therefore the candidates-tier evidence for the generator contrast, for length vs
size, and for the archaeological predictions. **It does not touch** entropy (Task A) or the
no-relative tier (the hidden language and its sister are excluded there).

**Verdict:** no answer-key leak, no scoring bug, not alphabetic. But the sister-language tiers are
optimistic for more reasons than previously stated, and one split defect exists. **Not clean enough
to start prose without your decision.**

Possible fixes (none applied, all need approval):
- (a) Split clauses by a hash of their CONTENT, so identical clauses fall in the same half, then rerun
  the related and candidates tiers. Generator/knowledge code only; methods stay frozen.
- (b) Report sister-tier numbers as upper bounds with the 35-point correspondence effect stated.
  Raw (untranslated) scores need a rerun, because per-corpus predictions were not stored.
- (c) The previously listed sister rebuild (mergers, splits, conditioned changes, divergent syntax),
  already future work.

## Item 3: longer inscriptions vs more inscriptions at equal total tokens (frozen original rule)

The length sweep holds 2,906 texts and varies mean length; the size sweep holds 4.6 signs and varies
the number of texts. Size accuracy is interpolated on log(tokens) between neighbouring size points, so
it has no interval of its own. The length points carry 95% intervals that resample whole languages.

| Run | Tier | ~17k tokens (6 signs) | ~29k tokens (10 signs) | ~58k tokens (20 signs) |
|---|---|---|---|---|
| v1 main | candidates | length 7.1 [1.1, 16.3] vs size 2.3 | **32.6 [14.9, 50.7] vs 3.0** | **43.6 [21.2, 65.3] vs 4.3** |
| v1 replication | candidates | 7.1 [1.7, 14.4] vs 3.1 | **28.6 [13.3, 45.6] vs 2.9** | **45.0 [24.1, 66.0] vs 4.1** |
| v2 | candidates | **35.9 [21.2, 52.0] vs 16.6** | **55.3 [35.2, 72.2] vs 19.7** | **50.1 [29.2, 70.5] vs 23.8** |
| v1 main | no relative | 2.4 vs 1.9 | 3.0 vs 2.1 | 4.2 vs 2.7 |
| v2 | no relative | 3.7 vs 3.4 | 5.6 vs 3.4 | 6.5 vs 3.5 |

Bold: the length interval excludes the interpolated size value. **Answer: yes, with a related
language among the candidates.** Under the frozen rule, longer inscriptions beat more inscriptions at
equal tokens in both generators, from 10 signs on (v1) and from 6 signs on (v2). Without a relative
both stay low, with a small edge for length (at most 6.5%). The revised rule shows the same direction
but weaker (v2: 51.1 vs 43.2 at 29k tokens). This headline rests on the candidates tier, so the item 4
caveats apply to its size.
